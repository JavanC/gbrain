# Key files: Fork — source write policy and post-write enrichment

[Subsystem index](../KEY_FILES.md). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.
These files are fork-owned (not in upstream gbrain); keeping their entries in a
fork-owned page means an upstream rebase never conflicts on them.

- `src/core/write-policy/` (`policy-v1.ts`, `load.ts`, `validate.ts`, `frontmatter.ts`, `gate.ts`, `contract.ts`) — source-scoped, opt-in page contract enforced before any write. A source repo declares `write_policy:` in its own `gbrain.yml` (found via `sources.local_path`); `parseWritePolicy` is fail-LOUD (a malformed policy resolves to `status: 'error'`, never to "no rules"), `loadWritePolicyForSource` caches by (path, mtime, size) so an operator edit takes effect on the next write with no restart. `validatePageAgainstPolicy` is the ONE normalizer+validator both `validate_page` (preflight) and the mutation funnel (gate) run, so a preflight pass guarantees the write is not policy-rejected: it fills `set_on_create_preserve_on_update` fields on create (`date` in the policy's IANA zone / `datetime` as ISO), lets the STORED value win on update (a full-content replace cannot drop `created`; a differing supplied value yields a `warning`, not a rejection), then checks required fields, non-empty list fields, longest-prefix directory→type rules, and connection-id shape (`slug_only` / `kebab`). `frontmatter.ts` splits/joins the leading YAML block on js-yaml (an upstream dependency), so the fork adds no package. `slug_rules.scope` decides whether an out-of-prefix slug is IGNORED (`known_prefixes`) or REFUSED (`require_known_prefix: true`); declaring both is a policy error, and `exempt_basenames` skips e.g. every README. `language_rules.body: english_first` refuses a body whose CJK ratio reaches `max_cjk_ratio` (default: the chunker's own `CJK_DENSITY_THRESHOLD`, via the shared `cjkRatio` in `src/core/cjk.ts`); it measures the COMPILED TRUTH with the timeline and the takes/facts fences stripped, and `exempt_slugs` globs skip directory signage. `buildWriteContract` projects the same policy (including a note that the language rule OVERRIDES the agent's own language instruction) into the `get_write_contract` payload so disclosure and enforcement cannot drift. `connection_rules.require_resolvable` defaults to `warn` — resolvability is order-sensitive and belongs to the repo lint. Rejection writes NOTHING; a policy that fails to load fails CLOSED with `write_policy_unavailable`. Sources with no policy keep legacy behavior exactly. Test seams: `__setWritePolicyOverrideForTests`, `_resetWritePolicyCacheForTests`, `_resetWritePolicySlugCacheForTests`. Authoring guide: `docs/guides/source-write-policy.md`; example block: `templates/write-policy.example.yml`. Pinned by `test/write-policy-parse.test.ts`, `test/write-policy-validate.test.ts`, `test/write-policy-ops.test.ts`, `test/write-policy-repo-lint-parity.test.ts`, `test/e2e/write-policy-put-page-pglite.test.ts`, `test/e2e/write-policy-postgres.test.ts`.
- `src/core/write-policy/mutation-gate.ts` — the gate's call sites, kept fork-owned so upstream files carry only small calls. `applyMutationWritePolicy` runs inside `persistence/page-mutations.ts:preparePageAdmission` (after slug validation and the subagent/client fences, before admission) only when the caller passes `writePolicy: true` — the `put_page` and `capture` op handlers (`ops/pages.ts`) and every `put_pages` member (`persistence/page-batch.ts`). Sync imports, file repair and internal maintenance rewrites submit `put_page` without the flag and are never judged: the repo's own files are governed by its lint, not the gate. A refusal throws `WritePolicyRefusal` (an `OperationError`); `submitPageMutation` turns it back into the `{ error, written: false, violations, … }` response via `writePolicyRefusalResponse`, and a `put_pages` member reports it as its refusal with the violations in `toJSON`. `isGatedOperation` limits the gate to `put_page`/`capture`. `previewWritePolicy` runs the same check from the `put_page` dry-run branch. `bypass_policy` is honored only for `ctx.remote === false`.
- `src/core/ops/write-contract.ts` — the READ half of the write policy: `get_write_contract` (what a source demands of a page) and `validate_page` (preflight a payload without writing), registered through the `operations.ts` façade as `writeContractOperations`. `resolveContractSourceId` mirrors `sourceScopeOpts`' precedence — an explicit `source_id` is honored only inside the caller's federated grant or for a trusted local CLI; an out-of-grant ask returns `source_not_permitted`. Both ops run the SAME `validatePageAgainstPolicy` the gate runs.
- `src/core/post-write-enrichment-submit.ts` + `src/core/post-write-enrichment.ts` — for an untrusted (remote) `put_page`/`capture`, the opt-in `writer.async_enrichment=true` queues a source-scoped `post-write-enrichment` Minion job so link reconciliation happens even on a `gbrain serve --http` deployment, which never runs the maintenance sweep itself. `withPostWriteEnrichment` is `submitPageMutation`'s one call: it attaches `async_enrichment` (`queued` / `skipped` / `error`; fail-open, never throws) and on an idempotent replay reports `{ skipped: 'replay' }` without queuing a second job. The job body runs upstream's own sweep pass `sweep.ts:runLinksTimelinePass` (exported for this) over the source's newest stale pages — the same extractor, endpoint resolution, managed-brain timeline publication, stale-edge reconciliation and watermark stamping the sweep uses — never the LLM-backed corpus ingest. Remote writes already get their `## Timeline` rows inline; link edges are what the job adds. `makePostWriteEnrichmentHandler` is registered in `commands/jobs.ts:registerBuiltinHandlers`. Pinned by `test/post-write-enrichment.test.ts` and `test/e2e/post-write-enrichment-postgres.test.ts`.
